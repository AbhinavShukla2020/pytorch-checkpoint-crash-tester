# PyTorch Checkpoint Crash Tester

A failure-injection harness for testing whether a PyTorch Distributed Data
Parallel job can survive a worker dying in the middle of a checkpoint. It runs
the same training workload twice—once uninterrupted and once with an injected
`SIGKILL`—then compares sample order, optimizer progress, and final model weights.

The checkpoint protocol uses one rank-local file per worker and publishes a
manifest only after every worker reaches the commit barrier. A restart ignores
directories without a valid manifest, so a partially written checkpoint is
never selected as the recovery point.

> **Practice-history note:** commit timestamps in this repository are deliberately
> distributed across a simulated March–June 2026 timeline for Git practice. They
> are not the original implementation or testing dates.

## What it verifies

- Model and optimizer state resume from the last complete step.
- Python, NumPy, CPU Torch, and CUDA RNG streams are restored per rank.
- The distributed sampler resumes at its exact epoch and sample offset.
- Incomplete rank files are ignored until a manifest is atomically published.
- Resumed and uninterrupted runs consume the same logical sample IDs.
- Optimizer-step counts and final parameter digests match exactly.
- The report records restart latency and how many optimizer steps were replayed.

## Quick start

Python 3.10+ and PyTorch 2.1+ are recommended. CPU-only runs use the `gloo`
backend, so a multi-GPU machine is not required.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
pytest
```

Run a two-worker crash experiment:

```bash
checkpoint-crash-test \
  --work-dir runs/demo \
  --nproc-per-node 2 \
  --steps 20 \
  --checkpoint-every 5 \
  --fail-rank 1 \
  --fail-step 10 \
  --fail-phase after-rank-write
```

The command creates isolated `baseline/` and `crash/` runs and writes
`runs/demo/report.json`. A successful report has `equivalent: true`.

To inspect checkpoint publication manually:

```text
checkpoints/
  step_00000010/
    rank_00000.pt
    rank_00001.pt
    manifest.json       # checkpoint becomes visible here
  step_00000015/
    rank_00000.pt       # ignored if the job died before publication
```

See [docs/protocol.md](docs/protocol.md) for the commit protocol and failure
model, and [docs/experiments.md](docs/experiments.md) for measurement guidance.

## Scope

This is a local correctness harness, not a replacement for a distributed
checkpoint service. It deliberately favors inspectable files and deterministic
replays over sharded tensor throughput. Measurements are generated by the
machine running the harness; no fixed restart-time or scale claim is bundled.
